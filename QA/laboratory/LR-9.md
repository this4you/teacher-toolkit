# Лабораторна робота: Тестування кошика в SauceDemo (Playwright + POM)

## Мета 🎯
Продовжити існуючий Playwright-проєкт і написати набір E2E автотестів для функціоналу **кошика (Cart)** на сайті **SauceDemo**.

У фокусі:
- Page Object Model (POM)
- **storageState** для логіну (логін 1 раз, без повторів у кожному тесті)
- стабільні селектори (переважно `data-test`)
- незалежні тести

---

## Сайт для тестування 🌐
- **SauceDemo:** https://www.saucedemo.com

---

## Передумови ✅
У [вашому репозиторії](https://github.com/this4you/playwright-saucedemo) (**клонуйте цей репозиторій локально**) вже є:
- `src/fixtures/baseTest.ts` (fixtures)
- `src/pages/LoginPage.ts`
- `src/pages/InventoryPage.ts`
- `src/pages/components/Header.ts`
- налаштований **storageState** через setup-тест (авторизація один раз)

> ⚠️ ВАЖЛИВО: у цій лабораторній **не можна робити логін у кожному тесті**. Тести мають використовувати `storageState`.

## Завдання 🧩

### Частина A — Розширити POM (Page Objects) 🧱
Додайте/розширте Page Objects і компоненти для роботи з кошиком.

#### 1) Створити `CartPage`
Файл: `src/pages/CartPage.ts`

Має містити:
- локатор списку товарів у кошику
- методи:
    - `open()` або `goto()` (відкрити `/cart.html`)
    - `expectOpened()` (перевірка, що відкрито Cart)
    - `expectItemVisible(name: string)`
    - `removeItem(name: string)`
    - `continueShopping()` (кнопка **Continue Shopping**)
    - `checkout()` (кнопка **Checkout** — тільки перехід, без тестів чекауту)

#### 2) Доповнити `InventoryPage`
Файл: `src/pages/InventoryPage.ts`

Додати методи:
- `addItem(name: string)`
- `removeItem(name: string)`
- `expectCartBadge(count: number)` (або `expectCartBadgeVisible(text: string)`)
- `openCart()` (можна реалізувати через `Header`)

#### 3) Доповнити `Header` component
Файл: `src/pages/components/Header.ts`

Додати:
- `openCart()`
- `cartBadge` / `getCartBadgeCount()` (залежить від вашого стилю)

> ✅ Вимога: тести мають працювати через POM — **без “жорстких” локаторів у тестах** (допускаються лише 1–2 винятки у дебаг-цілях, але не у фінальному рішенні).

---

### Частина B — Написати тести для кошика 🧪
Потрібно реалізувати **мінімум 5 автотестів** (можна більше) у папці, наприклад:
- `tests/cart/`

#### Обов’язкові сценарії (мінімум)

##### 1) Add one item → badge = 1 → item in cart ✅
- Відкрити `/inventory.html`
- Додати товар **“Sauce Labs Backpack”**
- Перевірити бейдж кошика = `1`
- Перейти в кошик
- Перевірити, що товар присутній

##### 2) Add two items → badge = 2 → both in cart ✅✅
- Додати **2 різні** товари
- Перевірити бейдж = `2`
- У кошику обидва товари видимі

##### 3) Remove item from Inventory → badge updates 🧹
- Додати 2 товари
- Видалити 1 товар **на Inventory**
- Перевірити бейдж = `1`
- У кошику лишився тільки 1 товар

##### 4) Remove item from Cart → badge updates 🧺
- Додати 2 товари
- Перейти в Cart
- Видалити 1 товар
- Перевірити бейдж = `1`
- Перевірити, що видалений товар **не відображається**

##### 5) Continue Shopping returns to Inventory 🏃‍♂️↩️
- Додати 1 товар
- Перейти в Cart
- Натиснути **Continue Shopping**
- Перевірити, що повернулись на Inventory (`/inventory.html`)
- Перевірити, що бейдж кошика залишився правильним (наприклад `1`)

## Додаткові завдання “Зірочки” ⭐ (необов’язково)
Виконайте будь-які **1–2** (або більше) для підвищення оцінки:

- ⭐ Перевірити, що після додавання товару кнопка змінюється з **“Add to cart”** на **“Remove”**
- ⭐ Перевірити, що після видалення останнього товару бейдж кошика **зникає** (або стає порожнім — залежно від UI)
- ⭐ Додати **snapshot**:
    - текстовий: `toMatchSnapshot()` для списку назв у кошику
    - або візуальний: `toHaveScreenshot()` для контейнера кошика
- ⭐ Використати `test.describe()` і теги (наприклад `@cart`)
- ⭐ Додати `beforeEach` (без логіну) для переходу на `/inventory.html`
